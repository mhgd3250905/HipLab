# 05 · 其它 App 的接入顺序与验证

## 迁移不是复制截图

先选明确版本的源码与规范，锁定一个已确认的页面，再迁移组件边界。HipLab 手册源为 `84202688b3c43015c0f8c66d8b9d7b07988f3e8b`；当前链接指向仓库文件，未来文件可能演进。要复刻这次体验，应先在目标工作副本核对所参考的 commit，而不是只按文件名取“最新版”。

| 层 | 先带走什么 | 目标 App 必须适配什么 | 最先做的样板 |
|---|---|---|---|
| 基础 | palette、排版、运动token、按压、线形功能图标 | 品牌色、字体资产/许可、locale、减少动画 | 一个按钮+一组行 |
| 页面 | HipNavPage/Bar/BackChip、route与covered response | 返回行为、系统样式、SafeArea、现有导航路由 | 首页→更多→设置→双标题选择器 |
| 控件 | ListGroup/Row、Switch、Slider、Segmented、确认框 | 状态源、持久化、disabled/错误策略 | 中英文、深浅的设置页 |
| 内容 | 静态装饰图标、媒体外框、友善插画模式 | 自有业务图形和文案 | 空态、正常、加载、错误页 |
| 复杂动效 | overlay身份、几何插值、邻牌预备、物理退场 | 媒体控制器、首帧、生命周期、native RGBA能力 | 两张牌（再加重复动作、短牌组） |

先实现一条真实导航链，再铺全 App。SDK 自带训练/聊天页仍由 SDK 的接口和版本约束负责，不为了“统一样式”把它复制进 App 重写。样例不会替你接入数据库、训练引擎、媒体服务或真实GPU资源。

## 一个可执行的复制顺序

1. 按[基础章](01-foundations.md)收齐依赖，复用目标 App 自己的主题与语言宿主。保留用户现有数据、业务ID和原SDK接口。
2. 建一个普通穿透顶栏页和一个固定头部页，验证上边距只计算一次。不要先复制全部业务页面。
3. 连通首页→更多（`pinLeading:false`）→设置（默认固定返回键）→含副标题的选择器，验证进入、返回、侧滑取消和键盘。
4. 把真实长英文、长中文、副标题、右侧meta和开关一起放进样板；用真实字体，不用占位短句替代排版验收。
5. 最后接动作牌。先让同一假媒体子树跨矩形展开/收回不销毁，再接SDK控制器、真实首帧和透明合成。
6. 用下面的“同身份”测试和真机录屏定位闪帧，先找发生重建/换面/裁剪的那一帧，不先加更长淡入。

## 导航验收：有明确可观察结果

| 场景 | 应当看到/量到的结果 |
|---|---|
| 列表静止与向上滚动 | 视口可到y=0；首行静止不被fade压暗；状态栏与顶栏不出现硬色带 |
| 更多→设置push中段 | 背景/玻璃/标题/右操作/底栏同行进；返回控制权只有一个 |
| 首页→更多 | 返回胶囊随目的页滑入，点击瞬间不先出现固定按钮 |
| 返回 | 下页持续存在，直接露出内容，无空背景闪屏 |
| iOS左缘拖动及取消 | 中段按手指1:1，取消后恢复当前页及其胶囊，不能留下下页胶囊 |
| 单标题→副标题→关闭 | 返回/关闭控件顶部坐标和44pt直径保持；增加的是标题/背景高度 |
| 键盘与底操作条 | 键盘高度只补一次，底条在键盘上方；不挤动返回键 |
| 减少动画/高对比 | 最终状态可操作；高对比玻璃不采样；零时长不留下遮罩或被隐藏控件 |

导航中间帧的视觉唯一性比“树中永远只有一个widget”更准确。恰好0帧允许两个完全重合的控件存在于不同路由；一旦转场推进，应只有目的页拥有视觉控制权。原测试定位见[导航章](02-navigation.md)。

## 设置和内容验收

| 检查 | 判定 |
|---|---|
| 分组与行 | 10圆角、30图标槽、58文字起点、0.5分割线；52/60是最小高度 |
| 长英文 | 标题可增长/换行，控件独立一行，不压缩成不可用小字 |
| 分段 | 显式设置ios模式与32/9/2，不使用通用34高默认冒充 |
| 开关/复合卡片 | 读屏能区分整行、开关和独立开始动作；Enter/Space保持可用 |
| 确认框 | 取消/外部关闭不能执行确认；文字不出现裸Text黄色下划线 |
| 立体图标 | 18类装饰角色静态；不新增无意义按钮、滤镜或帧回调 |
| 主题/语言切换 | 当前页面、组选择、聊天和媒体身份保留；用户原文不被改写 |
| 安全插画 | 小手机和深浅色均能看到完整人物及提示标记，无无脸模型/裁掉关键提示 |

## 媒体闪烁诊断：先区分哪一层变了

| 可见症状 | 首先查什么 | 有效修复方向 |
|---|---|---|
| 第一次展开卡，之后流畅 | 播放器创建、首帧、字体度量是否挤在过渡前几帧 | 有界预备、稳定子树、固定文字画布，展开完成才play |
| 关闭时动作突然跳成另一姿态 | 是否切回封面、seek回0或换第二个视频 | 原视频pause当前帧，原节点缩回 |
| 首页进更多闪一下 | route覆盖时是否淡掉/销毁媒体 | covered只压暗与停输入，持有真实暂停帧 |
| 下一张到顶闪一下 | 暖后牌晋升是否新建State/decoder | occurrence级身份接管；真实ready与冷牌锁封面分离 |
| 办公/居家或选组闪 | identity reset与晚首帧回调是否串到新计划 | 有限复用已就绪当前动作，其余用generation/key拦晚回调 |
| 纵向出屏时灰白残影/黑轮廓 | packed输入在透视/裁剪后如何取样 | 原生先合成完整RGBA；不要只加透明度或延时 |
| 下方补牌突然出现 | reserve是否到提交才append | 退场进度内从最底牌背后连续揭开 |
| 文件夹收回时首页先换了 | commit选组发生在reverse开始/route.pop Future返回时 | 等route.completed；恢复源图与退场同帧交接 |
| 动画尾端不能再次操作 | 是否等不可见的弹簧尾程才解锁 | 实际投影AABB完全离屏即可提交 |

冷牌“首帧ready”与“现在可以换掉封面”是不同状态。无转圈也不等于媒体已就绪。保持当前画面的机制要先正确，再隐藏等待指示器；真实失败仍需可重试。

## 性能定位顺序

1. 确定复现路径：首进/第二次、push/pop、主题/locale、冷/暖视频、方向和速度、窗口/键盘状态。
2. 验证布局、paint clip和layer归属，尤其是BackdropFilter在双页转场时是否采样整屏。布局宽高不是绘制裁剪。
3. 检查身份与初始化：不要在build、AnimatedBuilder里建controller、启动网络请求、重复准备字体或新建CurvedAnimation监听。
4. 检查每帧负担：固定文字布局画布、有限缓存和邻牌，不一口气预热整库。
5. 再在目标手机的对应渲染后端采集帧时序/录屏。区分UI线程、raster/GPU、解码/网络；单个框架frame timing指标不能等同整机GPU持续流畅度。

先排结构问题，不通过降低所有模糊、砍掉动画、加长时长、批量缓存视频或不断加RepaintBoundary来掩盖原因。每项改动应有能触发旧问题的复现和能说明机制的检查。

## 证据分层，不互相冒充

| 层次 | 能证明什么 | 不能替代什么 |
|---|---|---|
| 静态分析/样例编译 | API、类型、import和常见代码错误 | 视觉、原生纹理和手感 |
| Widget逐帧/几何/语义测试 | state identity、坐标、触达、交接时机、取消与减少动画 | 手机解码器/OES纹理合成 |
| 使用真实字体的组件截图 | 某尺寸的文字和布局 | 完整真机动态过程 |
| shader/native算法像素对照 | 指定输入/后端上的数学与RGBA消费 | 所有手机上均无闪烁 |
| APK核对 | 固定源、版本、资源、签名、payload | 已安装或用户已接受 |
| 原机逐帧录屏/性能trace | 特定设备/版本/路径上的实际问题与表现 | iOS/其它设备或未执行场景 |
| 用户验收 | 用户实际报告的体验与接受范围 | Agent没做过的逐项测试 |

## 直接可用的验证入口

本仓库已有的针对性例子：

```bash
flutter test --no-pub test/hip/hip_nav_anchor_test.dart test/hip/hip_nav_blur_bounds_test.dart
flutter test --no-pub test/hip/hip_ui_round2_test.dart test/hip/hip_transition_test.dart
flutter test --no-pub test/hip/hip_row_icons_test.dart test/hip/hip_ui_shared_completion_test.dart
flutter test --no-pub test/hip/hip_home_action_deck_test.dart test/hip/hip_home_routine_folder_test.dart
flutter test --no-pub test/hip/hip_app_locale_test.dart test/hip/hip_english_detail_test.dart
```

这些命令是维护与移植配方，不表示本次文档收束重新执行了全部检查。当前阶段的运行源、软件检查、真机和用户确认归[主线回执](../ui-main-integration-2026-11-07.md)及[验证台账](../verification.md)；本次新样例的实际检查在[文档收束记录](../ui-documentation-closeout-2026-11-07.md)中单独登记。

交给另一个 App 开发者时，应能回答：使用哪版规范、复制哪些组件、主题/locale如何接入、固定返回控制权属于谁、媒体身份何时改变、冷帧如何处理、哪种测试支持结论。若只能给几张截图或一段“加个弹簧”的描述，还不足以可靠复用。
