# UI r4 全界面审核与补全（2026-11-05）

本报告记录 PR #32 已确认的 iOS 设计语言之上的补全实现。审核基线为 `25260b30ec30f6242788e7de4ea0b01c17812aff`，工作分支 `codex/ui-r4-completion-20261105`。运行/构建源为 `6e247aa`；最终软件、包及设备证据见末节。后续台账提交只改文档，不改变运行源。

本轮保持已批准的玻璃材质、44/52pt 顶栏、44pt 返回胶囊、24pt 过渡带、颜色及页面缓动数值。具体标准见 [UI 设计规范](ui-design-standard.md)。SDK 内部聊天、动作详情和训练界面由 SDK 负责；不以 App 适配层替代 SDK 逻辑，不扩展字号或锁屏验收矩阵。

| 页面或流程 | 本轮处理 |

## 已确认的修复

### 共用导航、动画与操作区

- `HipNavPage`、覆盖页和主题路由过渡的 `CurvedAnimation` 改为明确创建、更新和释放，避免每次构建增加订阅。
- 普通与固定返回胶囊都在页面被覆盖时隐藏，保留进入/返回时的单一胶囊规则；标题层允许滚动手势穿透。
- `hipNavInset(context, hasSubtitle: true)` 使用状态栏 + 52 + 24；动作/套路详情、选择器和自测结果不再误用44pt标题行。
- `HipNavPage.bottomBar` 在共用骨架中只增加一份键盘高度；页面继续只处理自身底部安全区，使保存/添加操作保持在键盘上方。
- 首页“换一套”保持32pt视觉，玻璃按钮的点击布局至少44×44。
- 移除动画时，路由、覆盖层、分段、开关、按压、状态切换和确认弹窗直接呈现终态。审查发现的 iOS 边缘返回遗漏已修复：保留手势、取消视觉位移，完成/取消时零时长落定。
- 开关补名称、开关状态和键盘激活。复合组卡片通过显式 `preserveChildSemantics` 保留独立“开始 + 组名”动作，卡片本身仍打开编辑器；普通按钮默认行为不变。

### 页面与展示一致性

- 推荐套路卡片每张只计算一次当前 profile 的 `planFor`，分钟、动作数和缩略图与详情页使用同一计划口径；不改训练元数据或 SDK 计时。
- “套路复制为组”和本地动作“加入组 → 新建”两个编辑器入口改用 `HipRoute.content`。
- `HipAssessmentIntro` 持有唯一 `HipNavPage`，正文从 `hipNavInset + 12` 开始滚动，原开始按钮与快照 key 放入 `LibFooter`；外层不再重复导航骨架。
- 自测题目保留单屏判断与原布局，仅将旧关闭控件替换为当前平整关闭胶囊。
- 自测结果“换一条路线”复用 `showLibSheet`、`sheetTitle`、`HipListGroup/HipListRow`；有明确标题和“选择路线后开始训练”说明。路线名称去掉旧标称分钟后缀，meta 显示当前 profile 的计划分钟，正文保留 audience，列表可滚动。取消仍停留结果，选择仍调用原规划及开练流程。
- App 内隐私页将“内置视频/127.0.0.1”旧说明改为公共视频按需下载、缓存、目录更新及离线未缓存限制，更新日期为2026-11-05；本轮未据此改公开站点。

### 公共动作训练组导入 AI 的 App 异常

设备审查中出现 AI 入口无法打开。App 存储适配器导入普通训练组时，曾假定所有动作均有旧 action kit，并以 `kit(...)!` 读取默认剂量；公共目录动作如 `abs-A/abs-B` 没有此旧 kit，可触发本地导入异常并阻止 Coach 恢复。

`HiplabCoachPlanStore.planFor` 现对公共动作复用 `CustomStep.planItem(content)` 的既有投影，保留公共默认剂量、显式覆盖、动作顺序与组间休息；旧 kit 动作保持原投影，已保存的完整 SDK 计划继续严格解码。缺失训练定义仍明确报错，不放宽动作范围、SDK 入场或安全门禁，不重写已有训练组为 AI 计划。

公共训练组导入及既有存储回归共11项通过，包含真实公共两动作组重新载入、time/reps 覆盖、混合组顺序与休息、已有 SDK 计划和历史存储保持；真实模型调用不属于这组证据。测试见 `test/hip/hip_coach_public_group_import_test.dart`、`test/hip/hip_coach_chat_storage_test.dart`。

加载失败壳可返回和重试；开发诊断只记录异常类型及有限栈帧，不记录用户对话、凭据或异常消息正文。
