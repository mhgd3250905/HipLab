# HipLab 模型、动画与视频交付核对（2026-10-17）

**结论：人体模型和动作制作源真实存在，展示视频及高清交付尚未完成。** 45 个 MVP 动作中，18 个接入了视频、9 个只有静帧、18 个是占位；即 27 个动作尚无 App 内视频。现有视频可完整解码，但使用快速渲染和较低分辨率的交付配置，抽帧可见人物边缘偏软、细节有限。

本次只核对源文件、Git 记录、媒体参数、完整解码和界面逻辑，未更换 App 素材、未运行重渲染、未修改或安装手机 App。

## 模型与动画源交付

核对对象为 HipLab 内容包，以及 3D-Body 当前主目录和 [PR #119](https://github.com/mhgd3250905/3D-Body/pull/119) 的固定提交 `175ff31c29895f5730fc344519da6cbe1108ab30`。PR #119 的 Git 对象已取回，不改变 3D-Body 的工作分支或已有文件。

- 共用人体模型 `public/coach/flare-coach.glb` 实际存在，7,508,016 字节，含 16 个网格和 16 个蒙皮；各蒙皮引用 20 个骨骼。配套骨架、灰色人台头、肩颈修复、材质与制作引擎共 13 项固定源文件均存在，规范化 SHA-256 与 `models/training-human-v2.json` 全部匹配。
- 可编辑源 `assets/coach/flare-coach.blend`（10,015,683 字节）及 Snow 官方源 `.blend`（8,377,421 字节）均存在。本次没有在 Blender 中打开验证。
- 45 个 MVP 动作及 1 个备选动作全部找到对应 `.js` 动作规格。规格包含姿态、时间轨道、镜头、接触约束等，动作由脚本和求解器驱动；基础 GLB 中未烘焙这 45 个动作。
- 当前主目录只有上述 46 项中的 31 份规格，另 15 份 `n-*` 新动作规格在 PR #119。该 PR 的 15 份新动作及 6 份自测脚本共 21 份文件，SHA 登记、Node 语法及相对导入检查均通过。
- 因此，后续可继续在既有人体和动作源上制作，无需先重新建立整套模型；仍需实际渲染并逐项检查动作、接触、穿模、构图和循环。

## 视频缺口与交付记录差异

本机 `3D-Body/output` 扫描了 1,589 个 MP4。27 个 App 缺视频的 MVP 动作中，13 个找到同 ID 的旧库成片候选（7 个 `s-*`、4 个 `o-*`、`w-clamshell`、`t-seated-straddle-lift-1leg`），14 个 `h-*` 未在该扫描范围找到同 ID 成片。旧库视频的风格、版本和审核范围需单独检查，不能按文件名匹配后直接当成 HipLab 已交付视频。

动作表的 11 个 PR #113 `h-*` 写着“有（B 风格成片）”，实际在 App 中是 8 张静帧和 3 个占位，本次本机素材扫描也未找到对应视频。这些状态不能作为本地视频交付证据。另有 4 个 `o-*` 和 1 个 `t-*` 在动作表写“本地未见成片”，但本机旧库已有候选，说明表格也存在过时信息。

[PR #118](https://github.com/mhgd3250905/3D-Body/pull/118) 与 PR #119 已说明：第一批 15 个新动作及蝴蝶式使用 `glow-B / --pr 0.75` 快速渲染，精细版留给本地 4080；`s-9090` 的 B 版重渲中断，`s-seated-fold`、`h-squat` 等未完成 B 版重渲。原记录支持“制作源已提供、部分成片已接入、后续还需渲染”的判断。

PR #119 声称 15 个新动作 QA PASS，但该 PR 和本次本机输出扫描中未找到对应 `n-*` 的原始完整 QA 文件；本次未独立验证其全循环身体指标。19 条 App 视频完整解码成功仅证明文件可读取，不能替代动作质量验收。

## 画面模糊的实际来源

| 检查项 | 实际结果 | 对体验的影响 |
|---|---|---|
| App 内 MP4 | 19 条全部为 720×720 / 编码 30 fps；含 18 动作与 1 自测剪辑 | 大展示区在高分辨率手机上会放大源画面 |
| 视频压缩 | 全部视频约 3.02 MB，总码率约 106–257 kb/s | 体积偏小；码率本身不单独证明模糊，抽帧已观察到较软边缘 |
| 同步脚本 | 强制 `scale=720:720`、`fps=30`、H.264 `CRF 27` | 即使输入高清源，也会被降为这组交付参数 |
| 封面与静帧 | 9 张原型、20 张自测图、19 张 JPEG 封面全部 540×540 | 静态大图容易显得糊，不能视为高清动画帧 |
| 原型静帧 | 9 张各约 4.4–6.5 KB | 人物细节和边缘信息本来有限 |
| 源渲染 | 第一批登记为 `--pr 0.75`；渲染器默认画布 1080 并按该比例采样，再合成输出 | 快速版没有采用精细版的超采样配置；后续放大文件无法恢复缺失细节 |

已查看坐椅雨刷、蝴蝶式视频抽帧及 90/90 静帧，人物轮廓和细节确实偏软。直接把现有 MP4 放大成 1080 文件不能等同于重新高清渲染。

源码另有一项需要在重渲前统一：15 个 `n-*` 动作规格设 `fps: 15`，文档却描述母版 30 fps，App 文件也编码为 30 fps；记录未说明是否渲染时覆盖了该值。逐帧 MD5 不能在再次有损编码后可靠推断原始采样帧率，因此本次不判定现有视频只有 15 个独立动作帧/秒。

## 界面中哪些画面会动

首页大图、缩略图、结果卡和播放器“下一个”默认只展示封面；训练主体和自测主体才请求播放。首页图片不动不能用于判断对应视频是否存在。

| 自测项目 | 当前示范区内容 |
|---|---|
| 蝴蝶式 | 视频 |
| 90/90 | 540px 原型静帧 |
| 托马斯测试 | 视频 |
| 仰卧横跨 | 4.8 秒视频剪辑 |
| 坐姿体前屈 | 540px 中档自测对比静图 |
| 深蹲到底 | 540px 中档自测对比静图 |

后两项仍盖着“跟着做一遍”的标签，容易让用户误以为动画没有播放。实现位置为 `lib/hip/ui/hip_assessment_page.dart:242`。视频用 `contain`，静图默认 `cover`，两者裁切方式也可能产生切换差异。

## 建议的制作顺序

1. 在独立制作工作区准备 PR #119 的源文件，保留当前 3D-Body 和 App 已用素材；核对新旧动作规格与模型基准。
2. 先用“坐椅雨刷”现有快速版做高清对比样片，再用“90/90 坐姿换髋”验证缺片动作。统一真实采样帧率、精细渲染参数和 App 输出规格，以实际手机画面确定标准。
3. 标准确定后补齐 27 个缺视频动作，并处理现有 16 条快速渲染动作的精细版；旧库的两条复用成片另行判断是否需统一风格。
4. 更新同步脚本，避免高清样片导入时再次被固定压成 720/CRF27；封面也应从高质量源生成。
5. 对照每个动作的源提交、模型身份、完整循环 QA 和最终 App 文件更新台账。自测三项静图示范应补成视频或明确标为静态示意。
