# iOS 1.0 拒审与处理记录

2026-10-27 从 App Store Connect 只读核对：HipLab `com.ugk.hipinterlude`、1.0.0 (20) 的提交 `5f1196c4-3a44-4105-9833-4175e0fca7c5` 状态为 **被拒绝 / 问题未解决**，不是仍在等待审核。Apple 的问题类别为 **4.3 Design: Spam**，消息同时提及 **4.2.6 App Generation Services**。详情见 [App Review 提交](https://appstoreconnect.apple.com/apps/6806806172/distribution/reviewsubmissions/details/5f1196c4-3a44-4105-9833-4175e0fca7c5)。

审核员未指认其中某一条具体重复内容，而是给出重复、缺乏差异或商业模板等可能性。Apple 要求回答九个问题：功能、目标人群、市场需求、测试反馈、同账号产品、合并可能、共享代码/素材、第三方共享组件和内容提供方。Apple 表示若认为已符合规则，应先回复说明，不要直接重提；若确有相似问题，则要实质改进后再提交。不能把单纯改文案或生成新 Build 当作实质修复。

## 当前核对

- 同账号旧记录“开胯训练助手” `com.ugk.hiplab`、0.3.2 (7) 同样被拒，原因消息相同；本轮只读查看，未修改、取消或重新提交该记录。开哥已确认这是同一产品的旧提交，本阶段只推进 `com.ugk.hipinterlude` 记录。
- 同账号 `Flare 托马斯` 已可分发：其已发布版本介绍的是托马斯全旋 3D 分阶段教学、肌群视图和配套训练。HipLab 的核心则是髋部六项自报自测、方向评分/推荐、左右差异、动作库、自定义训练组与语音引导。[历史设计](../../hiplab-mvp-2026-10-16.md)及当前 `lib/hip/domain/` 可供佐证；不声称这些单项功能在市场上独有。
- 共享不是零：HipLab 的 `lib/core/` 媒体播放、本地资源服务和本机存储源于同账号 3D-Body/Flare 项目，部分视频素材亦来自该项目；`ugk_trainer` / `ugk_coach` 来自同账号 SDK，iOS 基础版不启用在线 AI。当前 Flare 源码也引用该 SDK；已发布 Flare 二进制的具体 SDK 内容尚未验证。
- 同账号还有被拒的 SmartFit 通用健身草稿；其更广泛的健身计划和媒体可能存在重叠，不能未经核实宣称完全无共享。其他可见产品包括 PushupAI、手腕训练助手及饮水类 App。
- 动作素材包含基于 Blender Foundation Snow 的 CC BY 4.0 衍生模型，见 `assets/licenses/Drill-media-ATTRIBUTION.md`。开源或授权素材可能被第三方使用，不能武断声称无人共享。
- 1.0.0 (20) 的 TestFlight 记录为账户持有人内部测试；真机安装和基础流程已看，声音/耳机及完整锁屏训练未通过专项验收。用户早前对转场过快、动画拥挤的开发反馈已形成修改并包含于 build 20；不将其包装成外部 TestFlight 反馈。
- `origin/release/1.0` 仍为 `8880c71`；`origin/main` 已另行前进至 `1083b49`，包含 Windows 端 SDK 和业务开发。不得把这些未针对本次 iOS 版本验收的改动自动带入 release，也不得覆盖 main 的新工作。
